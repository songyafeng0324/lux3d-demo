# T02 · 技术方案与契约

- **背景**：T01 已给出建议架构，尚未锁定部署资源、接口/数据合同及工程阈值。
- **目标**：在完整 MVP 范围内，把业务不变量落实为可实施、可验证的模块与合同。
- **输入**：产品 PRD、本轮需求补充、`docs/reviews/开发前评审.md`、宪章与计划；T03/T04 的验证结果用于收敛方案。
- **产出**：`docs/architecture/MVP技术方案.md`、`docs/contracts/数据与接口契约.md`、`docs/validation/MVP验收计划.md`，按依赖补实施任务卡。
- **验收标准**：明确技术栈及版本、模块职责、部署拓扑、身份/文件权限、事务与状态机、任务恢复、版本保存、快照与失效、迁移/备份；F01～F13 与 AC01～AC51 可追溯；所有未决项有责任角色和关闭条件；不同模型评审结论落盘。
- **状态**：完成（2026-11-04，v0.1 书面设计跨模型评审 PASS；T03/T04 真实参数验证后继续收敛）。
- **依赖**：云资源与预算暂缓；按已确认 D05/D06 和 11-04 本地优先指令设计。T03/T04 未验证参数保持开放。

## 必须回答
1. 任务受理、扣次、入队、入包、失败冲销各自的事务与唯一约束；跨表投稿互斥与展位交换如何保证。
2. worker 租约过期、旧 worker 返回与供应商结果未知时如何恢复；本站结算和供应商在途数如何分开。
3. 资源读取如何绑定本人/房间/展陈快照，同时被分享关闭及风险删除撤销。
4. 布局版本冲突、响应丢失、删除并发、未完成保存离开怎样反馈；不追加手动保存/实时同步功能。
5. 依据本地 MacBook、演示机与模型样本锁定验证条件，给出 11-16 目标的可行性判断与依赖，不静默缩减功能。

> 本卡产出是本地实施基线 v0.1，T05～T09 为后续待办；未把方案完成当作本机应用已运行。
