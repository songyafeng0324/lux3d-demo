# T14 · 双场景背包与小屋互访

**状态**　2026-11-07 已完成并在 Mac 本机验收，迁移 007 已应用。

## 目标与现状

在藏宝阁就能打开与小屋相同的背包，选图时看到白底提示。小屋第一人称从屋外台阶进入，并能发现和点赞其他分享的小屋。展品详情、审核及其他简介展示使用一致标签。

现有藏宝阁只挂载账号面板，小屋背包由 `Backpack` 提供。小屋第一人称共用室内入口，分享目前通过稳定链接访问。

## 需求与验收

| 项目 | 行为和验收 |
|---|---|
| 1. 两处背包 | 藏宝阁恢复「背包 B」按钮，直接打开同一个 `Backpack` 组件，登录、藏品、生成和投稿入口一致。自己的小屋两处背包入口标出 `B`，按键与点击使用相同逻辑。输入文字、其他弹窗或正在拖拽时避让快捷键。打开背包释放场景鼠标，沿用关闭按钮和 `Esc`。 |
| 2. 选图提示 | 在「选择一张图片」按钮旁显示「图片最好不要有背景，将背景处理为白色效果更好。」两处共用表单。 |
| 4–5. 作者与简介 | 藏宝阁 `E` 详情的用户投稿显示「作者：昵称」，官方条目保留「官方馆藏」标识。展品详情、后台投稿审核和资产详情等读取页统一显示「简介：…」，已有表单标签和保存的正文独立处理。 |
| 6. 参观出生点 | 自己的第一人称预览、分享页和「回到入口」使用同一出生点，站在正门外台阶最外侧中央并面向门口。脚底落在踏面内，若摆放遮挡则找附近可站立处。斜俯视布置相机保持原入口行为。 |
| 7. 逛一逛 | 登录后可从自己的小屋右上角打开榜单弹窗，展示所有已开启分享的小屋，包括已有分享，列出当前作者昵称、已保存小屋名、人气和「访问」。人气降序，同分按账号注册时间升序，再用房间 ID 固定完全并列的顺序。点击进入对应的 `/shared/:token`，关闭分享的小屋从最新列表移除。持分享链接可匿名参观。 |
| 8. 小屋点赞 | 分享参观页右侧放醒目的大拇指和人气数。每个已登录的非房主访客对同一间小屋只能赞一次，点完不可撤销。重复提交、刷新和换设备都按同一账号识别。默认零人气，榜单与详情取同一份点赞数。 |

## 范围与交互细节

- 原第 3 项由用户取消。生成沿用每账号最多一个未完成任务及现有派发规则。
- 按计划交互，关闭分享期间房间下榜且拒绝新点赞，重开后原有人气重新显示。点赞按房间及账号保存。

## 实施顺序

1. **确定契约**。将已确认的小屋榜单和点赞规则记录到产品增量及数据契约。
2. **共享背包和文案**。两个场景挂载同一背包组件，补齐快捷键、焦点和鼠标锁交互，集中完成选图及详情文案。
3. **互访与点赞**。以房间 ID 和点赞者账号 ID 建唯一关系。榜单接口检查登录，只读当前已分享房间的昵称、已保存名称、赞数和访问链接。服务端按登录身份、CSRF 和当前分享状态校验点赞，按唯一关系抗重复，并与关闭分享协调。分享模型沿用现有快照凭证。实现榜单弹窗、访问及点赞交互，处理加载、空列表、分享失效和已点赞状态。
4. **参观入口与 Mac 本机验收**。从现有 `PORCH_STEP` 几何推导入口，复用支撑面和摆放碰撞。用隔离 PostgreSQL 验证榜单登录校验、重复点赞、自己点赞、同分排序、点赞与关闭分享竞争和旧页面请求。Mac Chrome 验证双场景背包、输入避让、文案、实际出生点、双账号及游客分享路径。复用既有模型覆盖回归，完成独立复核并记录。
