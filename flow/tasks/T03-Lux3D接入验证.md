# T03 · Lux3D 接入验证

- **背景**：任务建立时，本机插件快照与官方帮助页示例有差异，完整中国区API Reference与真实生成尚未核实；本轮已取得当前官方schema并完成下述技术验证。
- **目标**：证明单张图片经中国区生成后能持久保存、校验并进入可预览资产流程，明确未知提交及失败恢复边界。
- **输入**：PRD E01/E03/E07、T01 R01/R02 及证据表、T02 合同初稿；用户已明确中国区。
- **产出**：`docs/contracts/Lux3D接入契约.md`、`docs/validation/Lux3D接入验证.md`；必要探针放后续确定的代码目录；真实产物使用验证环境持久存储，不把密钥或完整签名 URL 写入仓库。
- **验收标准**：记录当前接口来源及日期；核对提交/查询/状态/错误/输出/有效期/模型参数/并发及计费能力；有真实成功文件和渲染证据、原任务恢复及失败路径记录；未知提交有可实施对账和结束策略，不能自动重复 create；未解决项明确阻断范围。
- **状态**：完成接入技术验证（2026-11-04），真实单图/上传/分片/原任务恢复/离线交互/隔离入库通过，代码复审PASS。正式网站背包与worker、事务故障和完整输入策略由T06/T09落实。
- **依赖**：可用的中国区服务端配置、输入样本、目标环境和明确的生成验证费用范围；正式付费提交须基于实际方案和报价落实已有授权。

## 验证重点
- 11-04 本地优先更新：不依赖云服务器或公共云桶，先验证中国区上传本地图片的可用方式；供应商不能读取 localhost。探针在本地工程运行，真实费用和未知提交策略仍须落实。
- 新提交先持久化 attempt，获得供方 ID 后立即落盘；网页关闭、进程重启后恢复原任务。
- 供方成功到本站成功之间：文件落存、依赖完整、解析、材质、包围盒、渲染、最终数据库提交。
- 注入受控故障验证未入包不成功、原日返还一次、旧 worker 不覆盖新状态、迟到产物不复活终态或已删资产。
- 区分“故障模拟验证”和“供应商真实行为观察”；不为测试盲造多次付费任务，不把 API 读取失败写成生成失败。
- 若当前服务端没有幂等/可靠对账能力，记录具体限制及可接受终态策略，进入 T02 评审，不用本地请求键冒充端到端 exactly-once。

> 软件插件能生成资产不等于网站后端已接入；网站须依赖核验后的 API 合同，不依赖开发机插件缓存。
