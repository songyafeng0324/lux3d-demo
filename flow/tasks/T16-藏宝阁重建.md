# T16 · 藏宝阁重建

- **背景**：T10 的二层藏宝阁只有 24×28 m，层高 4.8 m，展品最大边 0.8 m，二层只有一圈过道；建筑是纯色方块，没有贴图和烘焙光；构件互相贯穿，碰撞坐标靠人工抄写，楼梯处脚会陷进台阶。用户否定了旧布局，要恢宏开阔的修仙藏宝阁。
- **目标**：按 [T16 重建设计](../../docs/design/T16-藏宝阁重建设计.md) 和 [D0 概念图](../../docs/design/t16/concepts/)，在 Blender 里建出新藏宝阁，替换首页场景。要做到零穿模，碰撞与建筑出自同一份源。
- **输入**：设计稿和[平面草图](../../docs/design/t16/plan-v0.svg)；风格参考与概念图；[贴图与摆件提示词](../../docs/design/t16/贴图与摆件提示词.md)，用户生成的贴图、Lux3D 摆件；现有 `apps/web/src/game/engine.ts`、`navigation.ts`、`follow-camera.ts`；`packages/contracts/src/gallery.ts`；T10 和 T15 的浏览器回归脚本。
- **美术源图**：[贴图与图案 PNG（13 张）](../../docs/design/t16/textures/) · [Lux3D 摆件参考 PNG（10 张）](../../docs/design/t16/props/)。
- **实施**（每阶段结束请用户看过再进下一阶段）：
  1. **D1 灰盒**：Blender 脚本按真实尺寸搭出整栋楼，包括碰撞集合 `Nav_Walk` 和 `Nav_Block`、30 个分档展位标记；导出 GLB 和导航 JSON，在网页中可实走；按台阶处理楼梯；用真实展品试放三档尺寸。
  2. **D2 结构与材质**：建模块化构件库，按木构搭接拼装；接入 Poly Haven 贴图和用户生成的图案；导出前自动检查穿插和共面，不通过不导出。
  3. **D3 光照与氛围**：Cycles 烘焙光照贴图；网页里加色调映射、辉光、雾、光柱、粒子、悬浮光环；加入天空、云海、浮岛；Lux3D 摆件入场；在地面反射的两种做法中按实测帧率选一种。
  4. **D4 收口**：KTX2 与 meshopt 压缩、实例化；回归测试和性能实测；另一个模型评审；写验证文档，更新 `CLAUDE.md` 里的导航约定。
- **会改的合同**：`exhibitFit` 改为按展位档位取尺寸（数据契约第 10 节）；`navigation.ts` 的几何数据改由 Blender 导出；30 个展位与数据库不变；小屋不受影响。
- **产出**：`scripts/blender/` 下的 T16 建模和导出脚本；`assets/t16/` 下的源文件、GLB 与布局/导航 JSON；网页接入代码；测试；`docs/validation/T16藏宝阁重建验证.md`。
- **验收标准**：
  - `npm run build`、`npm test` 通过，T10 和 T15 的浏览器回归在新场景下通过；
  - 导出时穿插检查为零；全场第三人称机位的镜头遮挡检查通过；
  - Mac Chrome 铺满视口时常态 ≥ 50 FPS；30 个展位都能放展品并按 `E` 查看；上下楼不卡、脚不陷；
  - 用户对照概念图认可；另由一个模型独立评审。
- **状态**：进行中（D1 已获用户确认；D2 结构与材质已完成，回归通过，待用户看实景确认；见 [验证](../../docs/validation/T16藏宝阁重建验证.md)）
