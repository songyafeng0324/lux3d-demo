# 模型缓存与网页副本验证（2026-11-12）

## 结论

- 第二次进入小屋、分享小屋或藏宝阁时，模型不再下载：每个模型只有一次约 255 字节的 304 往返。
- 第一次进入的下载量约为原来的 1/6：用户模型改为加载服务器生成的网页副本，画面与原文件一致。
- 撤销权限后立即失效：关闭分享后，访客浏览器里虽然还存着那份文件，用旧凭证请求仍得到 404，不会用本地那份。

## 做法

- 服务器：文件接口鉴权通过后才返回 `private, no-cache` 和以 sha256 为值的 ETag，匹配时回 304。规则见[数据与接口契约第 17 节](../contracts/数据与接口契约.md)。
- 网页副本：worker 为每个就绪模型生成一份（几何量化加 meshopt，贴图原尺寸转 WebP），网页用 `?variant=web` 加载，原文件保留不动。
- 前端：藏宝阁展品、小屋、模型预览和背包缩略图都改用 `cache: 'no-cache'` 请求副本，GLTFLoader 挂上 meshopt 解码器。

## 实测

### 真 Chrome 缓存（`node scripts/model-cache-browser.mjs <GLB…>`）

隔离临时库，两件真实 Lux3D 模型（13.3 MB、18.1 MB），各导入为官方物品（放进小屋）和官方藏品（上展位）。结果见 [result.json](evidence/model-cache/result.json)。

| 场景 | 第一次进入 | 第二次进入 |
|---|---|---|
| 屋主打开 `/room` | 5.88 MB（2 个 200） | 510 B（2 个 304） |
| 访客打开分享链接 | 5.88 MB | 510 B |
| 藏宝阁展品 | 5.88 MB | 510 B |

改动前同样两件模型每次进入都要 31.4 MB。关闭分享后，访客页里用旧凭证重新请求返回 404。

截图：[第二次进入小屋](evidence/model-cache/room-second-visit.jpg)、[第二次进入藏宝阁](evidence/model-cache/gallery-second-visit.jpg)。

### 副本大小与画质

- 本机库 29 个模型（开发 worker 自动生成）：原文件合计 314.2 MB，副本 45.7 MB，约 6.9 倍。
- 两件真实模型各从两个角度渲染原文件和副本：每通道平均差 0.12–0.31（满分 255），差值超过 24 的像素为 0。对照图：[左原文件，右副本](evidence/model-cache/original-vs-web-copy.jpg)。
- 生成耗时：每件 0.5–1 s（Mac）。

### 自动测试

- `npm test` 128 项通过。
- 集成测试（`npm run test:integration`，7 组）通过，新增：
  - `tests/web-copy.integration.mjs`：每个就绪模型排一次任务、只生成一次、已删除模型不生成、坏文件三次后放弃。
  - `tests/t07-room.integration.mjs`：ETag、强弱比较的 304、越权文件带缓存标记仍 404、副本经原模型鉴权、副本 id 直接读取 404、关闭分享后 304 失效。
  - `tests/t08-curation.integration.mjs`：风险删除同时删除副本并回收字节。
- 浏览器回归：`test:t10`、`test:t15`、`test:t08` 通过。

## 评审

提交前由 Sonnet 做了只读评审，没有高危问题。已修三条：生成中进程被杀时任务会反复重试（现在超过次数上限直接放弃）；副本记录事务回滚时对象文件残留；法线贴图改用质量 95。未改的两条：副本任务与生成任务串行执行，一件副本在服务器上约几秒，生成最多多等这么久；副本策略变更不会自动重建，要另写脚本。

## 注意

- 浏览器缓存可能被浏览器自行清理，清理后就是一次正常下载。
- 线上 Nginx 对 `model/gltf-binary` 开了 gzip，ETag 会变成弱标记；服务器已按弱比较处理。
