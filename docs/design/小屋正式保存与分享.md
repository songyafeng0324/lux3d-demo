# T07 · 正式小屋保存与分享

2026-11-05。沿用 courtyard-v1 单层私人小屋的几何与交互；二层公共藏宝阁沿用 T10 的独立建筑/导航合同，不把两个场景的尺寸混用。

## 为什么分开固定场景、资产和摆放

固定古建不进入用户布局。官方家具与本人背包模型各有真实资产 UUID、私有模型文件、归一化及 bounds；每次添加产生独立摆放 UUID，移除只撤下该次摆放。几何真相源仍为共享 contracts：`transformedBoundsCorners` 与 `validateRoomLayout` 对资产实际 bounds 的八角点执行正等比缩放、Euler XYZ 旋转和平移检查。

正式家具 GLB 来源于既有 `apps/web/src/scene/assets.ts#furniture`，导出脚本和 manifest 在 `scripts/build-furniture.mjs`、`assets/furniture/`。它们经过正式导入队列与真实 Chrome 渲染后发布，与个人生成资产使用同一模型交付策略。正式目录统一最长边归一化到1米、底部中心 pivot，用户可用等比缩放调整陈列；不套用实验页的固定家具尺寸常量。原始几何源码保持米制。

内置家具的来源记录使用不可登录的系统账号，password_hash 不符合任何可验证密码格式；它只满足私有文件/导入的来源外键，不创建新的可登录管理员。稳定 file/import ID 与源 SHA 保证重复初始化不重复发布、文件变化不原地覆盖、不复活已删资产。真正管理员仍按原 seed:admin 交互方式创建。

## 保存为什么保留请求和草稿

500ms 防抖、严格单队列，每次提交完整布局。只有 savedVersion/editSequence 有效回执才能确认对应编辑；后续草稿仍未保存，旧 ACK 不回弹正在拖动的物体。响应丢失保留原 key/body，重试先确认旧请求，再用新版本提交后续草稿。确定413/422拒绝时释放旧 pending，纠正后以新键继续；版本409停止自动写入，保留草稿，显式载入已确认版本才能继续。

服务端请求锁先于用户/资产/房间锁和回执查询，按 user → 排序后的旧、新资产 → room 锁定并重查，随后才校验 baseVersion。新 room_version 与当前指针、回执同事务提交；旧版不可变。布局没有件数上限；64MiB 是单次传输初值，超出明确拒绝，绝不截取一部分保存。

## 为什么稳定入口与参观凭证不同

稳定分享链接用于新进入者读取最新成功保存版本；256bit token 的 hash 建索引，原 token 用持久 APP_DATA_KEY 的 AES-256-GCM 加密保存，AAD 绑定 room ID。每次开关改变 epoch，重开沿用原链接。

访客每次进入取得当前版的独立256bit grant，绑定 room/version/epoch/期限。原页面与续期保持原版，不因为主人普通保存而切换布局；关闭后新进入、文件读取和续期均拒绝，重开也不复活旧 epoch。已加载画面无需主动清空。续期同样使用幂等键，其回执不保存明文 token。

访客只获得房名、主人当前昵称、固定场景、已摆放模型和必要变换/尺寸。不包含私有名称简介、原图、未摆背包、生成任务、投稿资料；没有详情/E提示/独立模型预览/下载入口。每次文件读取强制校验 grant 范围，有 grant 头时不允许回退主人 cookie；文件与分享响应均 private/no-store。

## 正式入口与界面

`/room` 是本人编辑和第一人称参观；`/shared/:token` 是免登录只读快照；首页菜单和背包均链接正式小屋。场景遵守沉浸式MVP约定：3D覆盖视口，地点/模式/保存状态为轻量HUD，物品库和摆放列表按需覆盖显示，不挤压3D画布。T04实验页保留独立，不作为正式权限或存储路径。

代码、实际浏览器与数据库结果见 [T07验证](../validation/小屋分享验证.md)；风险删除的完整引用清理由T08实现，本轮只建立“源资产已删后新文件/续期拒绝”的权限基础。
