# 部署说明（阿里云香港）

线上地址 https://yafeng.fun 。服务器为阿里云轻量服务器（香港，Ubuntu 24.04，4 核 8 GB，公网 IP `8.217.100.200`），选型理由见 `flow/decisions.md`。构建和测试都在 Mac 上做，服务器只负责运行。

## 日常更新

在 Mac 项目根目录运行：

```bash
bash scripts/deploy-hk.sh
```

脚本依次执行：
1. 在 Mac 上 `npm run build`。
2. 用 rsync 只传运行需要的文件：各包的 `package.json` 和 `dist`、`migrations`、运维脚本、官方物品 GLB。
3. 在服务器上 `npm ci --omit=dev`，然后迁移数据库、重启服务。
4. 等健康接口返回 `generationReady=true`。

仓库没有 Git 远程，服务器上不放源码和 `.git`。提交前的回归（`test:t10/t15/t08`）照常在 Mac 上跑。

## SSH

- 用 Mac 上的专用密钥 `~/.ssh/aholo_hk`，`~/.ssh/config` 里的 `aholo-hk` 条目已经配好，直接用 `ssh aholo-hk` 登录。
- 服务器只允许密钥登录，密码登录已关闭。
- Mac 上开着代理软件 TAG（mihomo TUN 模式）时，SSH 会被代理节点断开，报 `kex_exchange_identification: Connection closed`。所以配置里写了 `BindInterface en0`，让 SSH 走本机网卡直连。换成 Wi‑Fi 以外的网卡时要相应修改。
- 本机 `dig` 查到的 `198.18.x.x` 是代理软件返回的假 IP。要看真实解析，用 `curl "https://dns.alidns.com/resolve?name=yafeng.fun&type=A"`。

## 服务器布局

| 位置 | 内容 |
|---|---|
| `/opt/aholo/app/` | 运行代码（root 所有，所有人可读） |
| `/etc/aholo/aholo.env` | 配置和密钥（`root:aholo`，0640）：`DATABASE_URL`、`APP_DATA_KEY`、`LUX3D_CN_API_KEY`、`PUBLIC_ORIGIN=https://yafeng.fun`、`TRUST_PROXY=loopback`、`PG_BIN` |
| `/var/lib/aholo/data/` | `DATA_DIR`：`objects`、`staging`、`backups`（`aholo` 用户所有，0700） |
| PostgreSQL 18 | apt 安装的 `18/main` 集群，只监听 127.0.0.1:5432。库 `aholo_lux3d` 的所有者是 `aholo_app`，这个角色不是超级用户 |

`APP_DATA_KEY` 沿用 Mac 本机的值：分享 token、grant 等加密数据靠它解开，换掉就全部失效。它和每日备份里的 `app-data-key` 是同一个值，另外要在服务器以外再存一份。

## 进程

- `aholo-api.service`、`aholo-worker.service`：systemd 守护，以 `aholo` 用户运行，崩溃后 5 秒自动重启，通过 `ENV_FILE=/etc/aholo/aholo.env` 读取配置。
- worker 用系统安装的 `google-chrome-stable` 做模型渲染校验。服务器没有显卡，Chrome 走软件渲染，花草丛模型约 1.5 秒。
- 查看日志：`ssh aholo-hk journalctl -u aholo-api -u aholo-worker -f`
- 健康检查：https://yafeng.fun/api/v1/health/ready

## Nginx 与 https

- 配置文件 `/etc/nginx/sites-available/aholo`：反向代理到 127.0.0.1:3001，开 HTTP/2 和 gzip，上传上限 110 MB（后台模型上限 100 MiB）。
- `/assets/`（构建产物，文件名带哈希）由 Nginx 直接从 `/opt/aholo/app/apps/web/dist/assets/` 读取，带 `Cache-Control: public, max-age=31536000, immutable`，浏览器一年内不再请求。首页 `/` 是 `no-cache`，每次都会拿到最新的入口文件。
- Nginx 用 `$remote_addr` 覆盖 `X-Forwarded-For`，API 配合 `TRUST_PROXY=loopback` 只信任本机这一跳，限流按真实访客 IP 计算。
- 证书由 Let's Encrypt 签发，certbot 自动续期（`certbot.timer`），到期提醒发到用户邮箱。http 自动跳转到 https。
- 目前只解析了 `yafeng.fun`，没有 `www`。以后要加 `www`，先加 DNS A 记录，再执行 `certbot --nginx -d yafeng.fun -d www.yafeng.fun`。

## 备份

- `aholo-backup.timer` 每天 04:30 运行 `scripts/backup.mjs`，内容是数据库 dump、已提交的对象文件和 `app-data-key`，保留最近 7 天，位置 `/var/lib/aholo/data/backups/`。
- 如果当时有未确认的供方提交，这次备份会被拒绝，第二天再备份。查看结果：`journalctl -u aholo-backup`。
- 每日备份和数据在同一块盘上，防不了整盘损坏，所以还要在阿里云控制台开自动快照。
- 要把备份拉回 Mac：`rsync -a aholo-hk:/var/lib/aholo/data/backups/<目录>/ <本机目录>/`。

## 快照（阿里云）

- 轻量服务器**不支持自动快照**，只能在控制台手动创建：服务器详情 → 快照 → 创建快照。每台服务器最多 3 个。
- 建议在上线时、每次大的更新或改动服务器配置之前，手动创建一个快照；满 3 个就删掉最旧的。
- 快照和每日备份的区别：
  - 快照是整块系统盘的镜像，包括系统、软件、配置、证书和数据，可以把整台服务器回滚到拍快照那一刻，但它也存在阿里云这台服务器名下。
  - 每日备份只包含业务数据（数据库、模型文件、`APP_DATA_KEY`），恢复时需要先有装好环境的服务器。
- 要防止服务器整体丢失，就把每日备份拉回 Mac，用法见下一节。

## 把线上数据同步到 Mac

```bash
node scripts/pull-hk.mjs
```

- 默认只下载并校验，不改本机数据：先在服务器上新做一份备份，下载到本机 `data/backups/hk-<时间>-<id>/`，再到隔离的临时库里核对行数和每个文件的 sha256。下载下来的备份同时就是一份异地备份。
- 加 `--apply` 会用这份数据替换本机库和模型文件：
  - 运行前要停掉 `npm run dev`，脚本检测到网站或 worker 还在运行会拒绝执行。
  - 替换前会先备份本机现有数据，并检查本机 `APP_DATA_KEY` 与服务器一致。
- 方向只有服务器 → Mac。Mac 上的数据不会推到线上。
- 从 Mac 用 SSH 下载，跨境速度大约 0.5 MB/s，一次约 400 MB，要等十来分钟。

## 访问统计

```bash
bash scripts/stats-hk.sh
```

- 终端打印业务数据：注册人数、今日新注册、今日登录、生成任务和成败、开启分享的小屋、点赞数。
- 用 GoAccess 读取 Nginx 日志，生成网页报告并在浏览器打开，内容包括每天的独立访客、请求数、流量、页面和来源。
- 独立访客按「同一 IP 加同一浏览器、按天」计算。已排除搜索引擎爬虫，但公网上的扫描程序也会被算进去，所以数字偏高；看业务数据更准。
- Nginx 日志按 Ubuntu 默认设置轮转，保留 14 天。

## 首次部署记录（2026-11-12）

- 本机数据迁移：Mac 上 `npm run backup` 之后，在服务器上用 `pg_restore --no-owner` 恢复，对象文件逐个按 sha256 校验。共 4 个账号、35 件藏品、51 条文件记录，其中 43 个已提交对象全部校验通过。
- 演示账号 `t06_demo_20261105` 按用户要求改名为 `sh442901055`，昵称和数据不变。
- 迁移之后以服务器为准，Mac 本机库不再同步到线上。
- 实测：
  - 从 Mac 直连下载 13 MB 的藏宝阁 GLB：上午约 0.95 秒，中午约 80 秒，同时 SSH 下载约 0.5 MB/s。跨境链路到大陆的速度波动很大，是首屏慢的主要原因。用户第一次打开首屏用了 43 秒，第二次 2 秒（命中浏览器缓存）。
  - 服务器到 `api.aholo3d.cn` 建立连接约 35 ms。
  - 浏览器打开首页，`isSecureContext=true`、`crypto.randomUUID` 可用，控制台没有报错。
