# 本地运行

当前已完成 T05 基础工程：真实 API/数据库/私有文件存储/worker 心跳与工作台，T03真实接入与T04场景实验已验证，正式业务由T06～T09接入。

## 启动

在项目根目录运行：

```bash
npm ci
npm run local:setup
npm run dev
```

浏览器打开 [藏宝阁](http://localhost:5173/)（全屏第一人称参观）；[本地工作台](http://localhost:5173/workbench) 显示数据库/存储/worker 状态。关闭网页不会停止后台；在启动终端按 Ctrl+C 会停止 web/api/worker。PostgreSQL 单独保留运行，手动停止用 `npm run db:stop`，重启用 `npm run db:start`。Mac 睡眠期间不会持续处理，唤醒后重新连接。

本机已安装 PostgreSQL 18.6（Postgres.app 2.9.6）到 `~/Applications/Postgres.app`，二进制为其中 `Contents/Versions/18/bin`。独立项目实例只监听 127.0.0.1:55432，库 `aholo_lux3d`，应用角色 `aholo_app` 非超级用户且不能创建角色/数据库。不是系统默认 5432 实例。若换机器，先从 [官方页面](https://postgresapp.com/downloads.html) 安装 PG18，或设置 `PG_BIN` 指向已有 PG18 的 bin。

`local:setup` 创建项目专用集群、角色、数据库和两份迁移；再次执行不覆盖已有 `.env`、密码或业务数据。若现有 `.env` 的数据库配置失效，须按实际环境修正，不自动切库或重置密码。

## 位置与配置

- `.env`：项目私有配置，0600 权限且被 Git 忽略；不复制到前端或提交。
- `~/Library/Application Support/aholo-lux3d/postgres/`：数据库集群。
- 同级 `local-db.json`：仅本机数据库管理凭证，0600 权限，不在项目中。
- 同级 `data/objects`、`data/staging`、`data/backups`：持久对象、暂存与备份；不在 Web public。
- 同级 `postgres.log`：本机数据库日志。开发终端输出各进程状态。

中国区私有配置已核实，单图探针通过；网站生成worker/背包未接入，`generationReady=false`。基础服务 ready 不等于生成闭环完成。应用尚无默认管理员或示例用户；未来需要时在交互终端运行 `npm run seed:admin`，密码隐藏输入，重复同名账号不改密码或角色。

## T03 原任务诊断

中国区配置现在可读取 `LUX3D_CN_API_KEY` 或私有 `~/.config/lux3d/credentials.json` 的apiKeys.cn；可用 `LUX3D_CREDENTIALS_FILE` 指定私有文件。T03真实单图探针通过，网站背包/worker尚未接入，因此generationReady仍为false。

```bash
npm run probe:lux3d -- status
npm run probe:lux3d -- query
npm run probe:lux3d -- download
npm run probe:lux3d -- ingest
```

这些命令恢复原任务，不创建新生成；download刷新原任务临时链接并记摘要回执；ingest只写明确标记的本机T03验证库。原始签名URL和调用记录保存在私有Application Support/t03目录，不提交Git。

上传检查：`npm run probe:lux3d -- upload /本地图片绝对路径`；`npm run probe:upload:block` 用合法PNG验证真正分片。这些是联网上传检查，不是启动必跑项，不调用生成接口。当前GLB和自包含离线预览位置见 `docs/validation/Lux3D接入验证.md`。

## T04 场景验证页

`npm run dev`同时开启本地实验服务，访问 [场景验证页](http://localhost:5173/lab/t04)。可添加家具及T03真实模型，自动保存布置，切换小屋/30展位参观。实验数据在私有 `Application Support/aholo-lux3d/t04/state.json`，与主业务库分开；不是正式登录或PG业务实现。原GLB仅私有读取。

`npm start`默认关闭实验API；显式实验可设 `AHOLO_T04_LAB=1` 并保持127.0.0.1绑定。`T04_LAB_STATE_DIR`可指定独立实验目录，不应指向业务数据目录。

构建后 `npm run test:t04` 执行完整浏览器/负载验证；`npm run test:t04:input` 定向验证鼠标锁定、分享及删除。脚本在13004使用随机临时状态，不要求停止5173开发服务，也不写主业务库；13004须空闲。结果见场景验证文档。

## 构建与验证

```bash
npm run build
npm test
npm run test:integration
```

前两类测试不调用 Lux3D。数据库集成测试用随机独立测试库和临时文件夹，结束时清理，不写本人演示数据。

停止当前开发服务后运行 `npm run test:e2e`：它在 13001 启动独立 API 和 worker，以真实 Chrome 无头模式检查页面、API、worker 缺失与恢复，结束后停止测试进程。此脚本要求当前没有其他 worker 心跳，以验证缺失状态；常规开发入口为5173。截图在 `docs/validation/evidence/T05-local-workbench.png`。

打包运行：先 `npm run build`，两个终端分别 `npm start` 和 `npm run worker`，浏览器访问 [打包入口](http://127.0.0.1:3001/)。没有后台任务 worker 时 ready 会失败，live 仍可用。

## 备份与隔离恢复

```bash
npm run backup
npm run restore:check -- "/绝对路径/备份目录"
```

备份输出绝对目录，包含数据库 dump、committed 文件集合、hash manifest 和私有 APP_DATA_KEY（若配置）。目录0700，文件0600；不要公开整个备份。未决供方 dispatch 会阻止备份；未来所有业务写入/dispatch必须使用维护锁。

`restore:check` 校验摘要、恢复到随机新数据库和临时目录，核对行数及文件摘要后删除恢复副本，不覆盖原库。恢复副本永不启动真实create；生产恢复还必须对账备份之后的供方提交。该命令是恢复演练，不是覆盖式灾难恢复命令。
