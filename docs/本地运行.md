# 本地运行

当前已完成 T05 基础工程、T10 沉浸式首页与 T06 账号/额度/正式生成入背包；T07小屋保存分享与T08投稿/后台/展陈已实现，T09 本地功能验收结果与试用边界见 [MVP 验收结果](validation/MVP验收结果.md)。

## 启动

在项目根目录运行：

```bash
npm ci
npm run local:setup
npm run dev
```

浏览器打开 [藏宝阁](http://localhost:5173/)（全屏第一人称参观）；[本地工作台](http://localhost:5173/workbench) 显示数据库/存储/worker 状态。关闭网页不会停止后台；在启动终端按 Ctrl+C 会停止 web/api/worker。PostgreSQL 单独保留运行，手动停止用 `npm run db:stop`，重启用 `npm run db:start`。Mac 睡眠期间不会持续处理，唤醒后重新连接。

本机已安装 PostgreSQL 18.6（Postgres.app 2.9.6）到 `~/Applications/Postgres.app`，二进制为其中 `Contents/Versions/18/bin`。独立项目实例只监听 127.0.0.1:55432，库 `aholo_lux3d`，应用角色 `aholo_app` 非超级用户且不能创建角色/数据库。不是系统默认 5432 实例。若换机器，先从 [官方页面](https://postgresapp.com/downloads.html) 安装 PG18，或设置 `PG_BIN` 指向已有 PG18 的 bin。

`local:setup` 创建项目专用集群、角色、数据库和迁移；再次执行不覆盖已有 `.env`、密码或业务数据。若现有 `.env` 的数据库配置失效，须按实际环境修正，不自动切库或重置密码。

## 位置与配置

- `.env`：项目私有配置，0600 权限且被 Git 忽略；不复制到前端或提交。
- `~/Library/Application Support/aholo-lux3d/postgres/`：数据库集群。
- 同级 `local-db.json`：仅本机数据库管理凭证，0600 权限，不在项目中。
- 同级 `data/objects`、`data/staging`、`data/backups`：持久对象、暂存与备份；不在 Web public。
- 同级 `postgres.log`：本机数据库日志。开发终端输出各进程状态。

中国区私有配置已核实，正式生成worker和背包已接入。启动时执行 `npm run db:migrate` 后，配置有效且worker可用时 `generationReady=true`；`LUX3D_GENERATION_ENABLED=0` 可禁用新生成，已有供方ID仍允许原任务查询与交付。应用无默认管理员；需要时在交互终端运行 `npm run seed:admin`，密码隐藏输入，重复同名账号不改密码或角色。

## T03 原任务诊断

中国区配置现在可读取 `LUX3D_CN_API_KEY` 或私有 `~/.config/lux3d/credentials.json` 的apiKeys.cn；可用 `LUX3D_CREDENTIALS_FILE` 指定私有文件。T03探针保留隔离诊断用途；正式账号与worker已由T06接入，操作见下节。

```bash
npm run probe:lux3d -- status
npm run probe:lux3d -- query
npm run probe:lux3d -- download
npm run probe:lux3d -- ingest
```

这些命令恢复原任务，不创建新生成；download刷新原任务临时链接并记摘要回执；ingest只写明确标记的本机T03验证库。原始签名URL和调用记录保存在私有Application Support/t03目录，不提交Git。

上传检查：`npm run probe:lux3d -- upload /本地图片绝对路径`；`npm run probe:upload:block` 用合法PNG验证真正分片。这些是联网上传检查，不是启动必跑项，不调用生成接口。当前GLB和自包含离线预览位置见 `docs/validation/Lux3D接入验证.md`。

## T04 场景验证页

`npm run dev`同时开启本地实验服务，访问 [场景验证页](http://localhost:5173/lab/t04)。可添加家具及T03真实模型，自动保存布置，切换小屋/30展位参观。实验数据在私有 `Application Support/aholo-lux3d/t04/state.json`，与主业务库分开；不是正式登录或PG业务实现。原GLB仅私有读取。

`npm start`默认关闭实验API；显式实验可设 `AHOLO_T04_LAB=1` 并保持127.0.0.1绑定。`T04_LAB_STATE_DIR`可指定独立实验目录，不应指向业务数据目录。

构建后 `npm run test:t04` 执行完整浏览器/负载验证；`npm run test:t04:input` 定向验证鼠标锁定、分享及删除。脚本在13004使用随机临时状态，不要求停止5173开发服务，也不写主业务库；13004须空闲。结果见场景验证文档。

## 构建与验证

```bash
npm run build

npm run test:integration
```

前两类测试不调用 Lux3D。数据库集成测试用随机独立测试库和临时文件夹，结束时清理，不写本人演示数据。

停止当前开发服务后运行 `npm run test:e2e`：它在 13001 启动独立 API 和 worker，以真实 Chrome 无头模式检查页面、API、worker 缺失与恢复，结束后停止测试进程。此脚本要求当前没有其他 worker 心跳，以验证缺失状态；常规开发入口为5173。截图在 `docs/validation/evidence/T05-local-workbench.png`。

打包运行：先 `npm run build`，两个终端分别 `npm start` 和 `npm run worker`，浏览器访问 [打包入口](http://127.0.0.1:3001/)。没有后台任务 worker 时 ready 会失败，live 仍可用。

## 备份与隔离恢复

```bash
npm run backup
npm run restore:check -- "/绝对路径/备份目录"
```

备份输出绝对目录，包含数据库 dump、committed 文件集合、hash manifest 和私有 APP_DATA_KEY（若配置）。目录0700，文件0600；不要公开整个备份。未决供方 dispatch 会阻止备份；未来所有业务写入/dispatch必须使用维护锁。

`restore:check` 校验摘要、恢复到随机新数据库和临时目录，核对行数及文件摘要后删除恢复副本，不覆盖原库。恢复副本永不启动真实create；生产恢复还必须对账备份之后的供方提交。该命令是恢复演练，不是覆盖式灾难恢复命令。

T09 已用含业务数据的正式库备份演练隔离恢复，核对 8 个对象的摘要，并在恢复副本中重新登录和打开加密分享。另保留一次本机空业务库备份：`data/backups/6b045cbb-7367-43af-9d3c-8ee6cebd87b9/`。另有含二进制fixture的隔离恢复测试通过，fixture已清理。

## T06 正式账号与背包

打开首页、进入古阁后按 B，在背包内注册/登录。单图支持PNG/JPEG/WebP、最大10MiB和16MP；系统固定生成参数，不要求先写名称。每日北京时间3次，单用户最多1个未结束任务，模型实际可预览才入包。关闭网页后worker继续；丢响应选择“确认原生成请求”继续同key，避免重复提交。

测试账号 `t06_demo_20261105` 已保留真实模型；登录资料仅在私有 `~/Library/Application Support/aholo-lux3d/t06/site-account.json`，不要提交Git。可自行注册普通账号；管理员仍用seed命令创建。验证结果见 [T06验证](validation/账号资产生成验证.md)。

```bash
node scripts/t06-live.mjs status
node scripts/generation-diagnose.mjs list
# evidence <private-evidence.json>仅记录原调用/供方确认的精确nonce和ID
# reconcile <attempt-uuid>仅查原任务，不create、不复活已失败任务
node scripts/t06-live-browser.mjs
```

`node scripts/t06-live.mjs submit` 是已授权T06测试批次的恢复入口，读取同一私有task/key与1积分上限；不能用来追加测试候选。普通用户实际生成走背包按钮。模型导入基础API只支持静态自包含GLB，家具/官方候选经相同渲染验证才发布，后台完整UI留T08。

新增回归：`node --test tests/t06-api.integration.mjs tests/t06-worker.integration.mjs`（随机独立PG）；运行开发服务后 `node apps/web/scripts/t06-ui-check.mjs` 与 `node apps/web/scripts/t06-pagination-check.mjs`（拦截API、不调用供方）。

## T07 正式小屋与分享

从首页菜单/背包点击“个人小屋”，或直接打开 [小屋](http://localhost:5173/room)。登录后点击“打开物品库”，从官方家具或本人背包添加，三轴编辑、列表定位/移除与房名修改均自动保存；刷新恢复最后确认版本。`/lab/t04`仍为独立实验，不用其状态覆盖正式小屋。

`npm run local:setup`会幂等导入3件本地家具；既有环境可运行 `npm run seed:furniture`。来源GLB和hash在 `assets/furniture/`，重建用 `npm run build:furniture`；不调用Lux3D，系统来源记录无法登录，不代替交互管理员种子。

开启分享后可在界面复制稳定 `/shared/:token` 链接。访客免登录只读，关闭后阻止新进入/新文件，重开原链接可用但旧grant不复活。演示账号已保留5件陈列，私有本机分享链接在Application Support/t07/share-url.txt。访问仍遵循当前本地回环服务范围。

```bash
node scripts/t07-browser.mjs
node apps/web/scripts/t07-ui-check.mjs
node --test tests/room-save.test.mjs tests/room-geometry.test.mjs
```

第一条使用正式演示账号与真实API布置验收，不新增生成；第二条拦截API执行隔离UI回归；数据库专项为 `tests/t07-room.integration.mjs`，在随机独立库测试12000件、CAS/幂等/授权/关闭重开。实际结果见 [T07验证](validation/小屋分享验证.md)。

## T08 投稿、后台与展陈

- 首页按 B 打开背包，在藏品详情“申请加入藏宝阁”补齐公共资料提交；“投稿”栏查看状态与驳回原因。
- 管理后台 [http://localhost:5173/admin](http://localhost:5173/admin)：投稿审核、候选与30展位、资产上传/维护/风险删除、用户与当天调额。主库正式管理员 `aholo_admin` 已建，密码在私有 `~/Library/Application Support/aholo-lux3d/t08/admin-account.json`；另建管理员用交互终端 `npm run seed:admin`（家具系统来源账号不能登录，也不要改它）。`npm run demo:t08` 可重复运行，只追加、不删除。
- 升级后执行一次 `npm run db:migrate`（迁移004）。`npm run test:t08` 在127.0.0.1:13008用随机临时库与临时目录跑Chrome验证，结束自动删除，不写主库；需先 `npm run build`，13008须空闲。


## T09 完整验收复现

在用户 Mac 的仓库根目录执行。构建、单元、集成、基础烟测和策展回归使用上文命令。保留原工作区私有配置与演示账号。以下场景复用已完成的真实任务，无新增付费生成。

1. 用独立端口启动打包 API，保持该终端运行。

   ~~~bash
   API_HOST=127.0.0.1 API_PORT=13009 PUBLIC_ORIGIN=http://127.0.0.1:13009 LUX3D_GENERATION_ENABLED=0 npm start
   ~~~

2. 在另一终端核对正式背包、匿名分享和展陈，走完古阁往返。正式站请求会产生常规会话和参观凭证。测试布局、展位和资产写入使用隔离库。

   ~~~bash
   node scripts/t09-acceptance.mjs main
   T10_BASE=http://127.0.0.1:13009 T10_EVIDENCE_DIR=docs/validation/evidence/t09/t10 npm run test:t10
   ~~~

3. 备份并使用命令输出的实际备份目录进行恢复。T09 恢复脚本需 13010 空闲，会在临时库运行十会话负载、双会话小屋和 30/100 件性能样本，完成后清除测试库和文件副本。

   ~~~bash
   npm run backup
   npm run restore:check -- "/备份目录绝对路径"
   node scripts/t09-acceptance.mjs restore "/备份目录绝对路径"
   ~~~

另一次 PostgreSQL 重启演练使用同版 PG 临时集群，经私有 Unix socket 恢复同一份 dump。重启前后查询已交付任务的终态、供方 ID 及模型 SHA，逐值一致后停止并清理临时集群。这是单独执行的一次演练。

正式库真实主链路检查使用已保留的 T06 资产、可访问的稳定小屋分享以及已发布展位。若演示数据改变，请以当前状态核对前置。结果与试用边界见 [验收结果](validation/MVP验收结果.md)。
