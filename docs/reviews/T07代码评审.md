## 已关闭发现

- **P2 → PASS：访客续期请求缺少 Idempotency-Key。** 初版前端自动续期只携带 Authorization，而后端 `requestWrite` 强制要求幂等键，必定返回 422。修订版每轮保留稳定 key，并发送 grant ID 与 token；网络/5xx 不确定失败 30 秒后用原 key 重试，成功后下一周期换 key，明确 4xx 拒绝后停止重试。续期继续绑定原 grant 和原版本，不重新获取当前布局。
- **P2 → PASS：正式小屋沿用 T04 框式页面。** 主线补核发现初版常驻白色侧栏和页面框架不符合 `DESIGN.md` 与沉浸式 MVP 实施计划第 3 节。本次已补读合同，并复核最终 `room.css` / `Room.tsx`：页面 fixed/inset:0，workspace/stage/canvas 绝对定位覆盖视口；标题、状态与工具为墨底金线 HUD；物品库/摆放列表默认关闭，通过按钮打开浮层抽屉，关闭按钮或 Esc 收起，不挤占 canvas。owner 与 visitor 共用全视口规则，visitor 不渲染编辑抽屉。该项代码合同缺口已关闭，最终浏览器尺寸与交互证据由主线保留。

## 后端与授权检查

- **PASS：CAS 和重放顺序。** 请求级 advisory lock → 身份/资源重查 → receipt → baseVersion 检查。同键等待者返回原 savedVersion/editSequence；新键过期版本返回 409/currentVersion。每次成功写入新 immutable room_version 后推进当前版本；没有覆盖历史版。
- **PASS：锁序。** 会话重查锁 user；发现旧、新布局资产并去重排序，锁 assets 后锁 room。若发现新的旧版资产则回滚重试，不在持 room 锁时逆序追加资产锁。授权检查仅允许本人 ready personal 或 ready furniture，且模型文件须 committed。
- **PASS：无固定件数截断。** 布局按完整数组验证/保存/返回；前端读完所有目录页，模型只限制并行解码数量。请求体超过 64MiB 会明确 413，不截取部分内容。共享 bounds 函数校验变换后的八角点，支持真实资产 UUID/尺寸与重复摆放。
- **PASS：稳定链接。** 随机 256bit token 的 hash 用于查找；原 token 使用 AES-256-GCM 和 room ID AAD 加密保存。开关改变 epoch，不更换稳定入口；写回执只存是否存在 URL，不保存明文 token。
- **PASS：快照隔离。** 新访客领取当前已确认版本的 256bit grant；grant 绑定 room/version/epoch/expiry。旧版普通移除不改变旧 grant 范围；关闭重开后旧 epoch 仍不可用。续期重新检查有效性并保留原版本，不能借原幂等回执绕过撤销。
- **PASS：文件授权优先级。** 只要请求携带 snapshot 认证信息，就强制走 grant 范围；即使同时有主人 cookie，也不能读取该版未摆模型或原图。文件请求检查 grant token/ID/期限/epoch、资产 ready、文件 committed，并返回 private/no-store。
- **PASS：分享 DTO。** 仅房名、主人昵称、固定场景、布局、必要模型 bounds/normalization/fileId 和 grant；未包含背包、原图、资产私有名称简介、生成任务或投稿资料。

## 前端与家具检查

- **PASS：自动保存。** 500ms 串行防抖；在途后续编辑保留当前草稿，ACK 只确认对应 editSequence。网络失败保留原 key/body；400/413/422 确定拒绝清原 pending 并允许新草稿；409 停止自动写入并要求显式载入已确认版。
- **PASS：拖动与读取失败。** 保存状态回调不替换相同 placements 引用，engine 同时避免改写正在拖动的对象。模型/房间读取成功前不开始提交空布局；载入失败保留阻断状态。参观模式不写布局，分享入口不创建 owner saver。
- **PASS：模型与资源。** 私有或 grant 模型通过受保护 content 端点获取；浏览器 GLTFLoader 拒绝外部 URI；应用 normalization 后再应用摆放变换。移除摆放不删除背包资产，所有摆放保留独立实例 ID。
- **PASS：官方家具来源。** 本地 Three.js 作者源导出 GLB，无供方调用。manifest 绑定 SHA，固定导入/file ID 确保重跑不重复导入；内容变化或文件非 committed 时明确拒绝，不原地替换/复活。专用 system 账号使用不可验证的 password_hash，并核验既有身份冲突，不提升现有同名普通用户。worker 仅处理明确 import refId。
