## 资源问题与复查结果

1. **P1 → PASS：GLB accessor 解码内存预算。** 初版 `inspectModel` 对 POSITION 只检查 count 为正整数；使用 indices 时三角面预算仅看 indices.count。实际构造的 **432 字节** GLB，POSITION count 为 `1000000000`、无 bufferView，indices count 为 3，初版返回 triangles=1 并接受。已安装的 `GLTFLoader.js` 对无 bufferView accessor 直接执行 `new TypedArray(accessorDef.count * itemSize)`，该例会尝试分配约 12GB。复现只调用 inspectModel，未执行危险浏览器加载。修订版对所有 accessor 增加 count 上限、单项 32MiB/合计 128MiB 解码预算、POSITION 总顶点 90 万限制，并核查 view/stride/sparse 边界；拒绝用例已通过。
2. **P2 → PASS：实例与变形目标放大。** 初版 mesh 三角面预算未计 node 实例，4096 个 node 重复引用可把实际每帧负载放大至约 12 亿面。修订版对全部 node 实例累计不超过 30 万面/256 个 mesh 实例，并拒绝多父与环；静态 MVP 同时拒绝 skin/animation/morph targets/weights，拒绝 extensionsUsed 及所有嵌套非空 extensions，封闭 `EXT_mesh_gpu_instancing` 和 morph GPU 纹理绕过预算的路径。相应用例已通过。

## 静态检查通过的边界

- `prepared → dispatch_started` 先于 create 持久化；未知/崩溃恢复路径不重新 create；历史查询不按近似时间认领任务。
- 请求级 advisory lock 先于业务锁与回执读取；身份与资产撤销检查先于回放。同键并发结果与业务事务同提交。
- 单用户在途限制有行锁和部分唯一索引；reserve/refund 事件唯一，退款使用原 submitted_day，并与最终失败同提交。
- 生成成功要求真实 GLTFLoader/WebGL 渲染、持久文件与 SHA、attempt/providerTask/input/request 来源匹配；成功发布事务重查 fence 和非终态。已失败任务不复活。
- 模型不允许外部 buffer/image URI；验证浏览器只允许本次回环服务网络，下载不跟随重定向，体积有上限。
- 私有文件每次请求重新检查 session、文件 committed 与当前资产权限，返回 private/no-store；资产编辑回执前重新检查资产 ready/归属。
- 后台导入创建与请求回执、逻辑 job 同事务；发布与导入结果、候选占用同事务，唯一 import_id 防重放。
