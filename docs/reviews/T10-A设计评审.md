## 非阻断观察与明确后续验证

1. **平台路径要向内收，不能原样用作角色中心轨迹。** `layout-draft.json`的`stair.ascendingPath`两个中间点位于`z=-11.5`，正是平台南缘；`build-layout.py:17—18`同样如此。跨越中央0.6m梯间缝时，有限半径角色可能越出平台或碰到护栏。T10-B/C需把折返轨迹移入平台、确定角色半径与扶手厚度，再验证上下行转弯；草案已将角色半径与平台收口列为待验证（说明第33行），因此本项不否定设计级连通意图。
2. **尺寸标注需在模型中兑现。** `build-layout.py:94`将2.4m写为“单梯净宽”，但JSON的梯井宽度恰为`2.4 + 0.6 + 2.4 = 5.4m`，没有另列扶手/护栏占位。建模时明确2.4m是完成面净宽还是概念梯带宽；必要时调整梯井。北侧横向路线（脚本第59行）距角柱外缘最近仅约0.3m，名义2.2m不能替代带角色半径的通行验证；可移动路线或调整局部布置。
3. **围护目前仅有规则，没有可测几何。** T10-B须明确中庭四边、梯井周边、中央梯侧以及一层禁入楼梯下方的实体/碰撞边界，并保留正确的一层入口和二层出口。T10-C实测入口→上楼→环廊→下楼全程，包含贴边、斜走、回退、转弯和低帧率连续碰撞；同时检查踏步收口、梯口净高及楼板厚度。
4. **下次改布局时同步生成源。** 当前脚本第7—25行内置参数并写出JSON，第42—59、84—94行还有绘图参数常量，并非读取已有JSON后自动绘图。本次值一致，但单改JSON后重跑脚本会覆盖修改；后续迭代应统一参数入口或同步修改并复核JSON/SVG/PNG，避免“JSON优先”的阅读约定与生成行为产生漂移。
5. **视觉与交互在B/C实证。** 用实际粗模保留入口、二层两机位，对照缩小天窗后的明暗与古建气质；检查展品尺度和30位浏览体验。浏览器验证全视口、背包覆盖而不挤压画布、移动键清空、Pointer Lock释放/恢复、详情/菜单/E输入互斥，并检查保存回执不重置拖动；性能与资源来源按T10任务卡留证。本评审没有把上述未实施事项记为通过。
